# Process

## How work is organized

Tasks are GitHub issues. Work one issue at a time.

Before starting a task, read its acceptance criteria in the issue body.
Before closing a task, re-read the acceptance criteria and confirm each point is met.

Commit regularly — at least after each logical step, not just at the end of a session.
Commit messages should say why, not just what. Use `gh issue close <number>` when done.
